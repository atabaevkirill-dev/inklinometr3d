# Прошивка тестовой платформы (ESP32)

Платформа 200×200 мм, сверху три инклинометра, снизу — три опоры: регулировочные винты (ручное выравнивание)
или сервоприводы с рычагом (самовыравнивание). ESP32 читает датчики 100 раз в секунду, фильтрует,
голосует «2 из 3», сам выставляет сервы и шлёт всё на сайт (`live.html`) по USB или Wi-Fi.

## Почему ESP32

| | ESP32 | Arduino Uno/Nano | Raspberry Pi |
|---|---|---|---|
| Связь с сайтом | Wi-Fi + USB | только USB | Wi-Fi + USB |
| Память | 520 КБ | 2 КБ | гигабайты |
| Логика | 3.3 В — как у точных датчиков | 5 В — нужны преобразователи | 3.3 В |
| Шаговые моторы потом | да, аппаратные таймеры | слабо | нет реального времени |
| Цена | ~5–8 $ | ~3–20 $ | 35+ $ |

Для большой конструкции: ESP32 (или STM32) управляет моторами; Raspberry Pi или ПК — только пульт.

## Инклинометры для ESP32

Все варианты ниже — 3.3 В, подключаются к ESP32 напрямую, без преобразователей уровня.

| Датчик | Интерфейс | Что это | Точность по горизонту* | Для чего |
|---|---|---|---|---|
| **Murata SCL3300** | SPI | готовый инклинометр (3 оси, угол считает сам) | ≈0.01°, разрешение 0.0055°, мало плывёт от температуры | **рекомендую** — основной вариант |
| Analog Devices ADXL355 | SPI (или I2C) | малошумящий 20-битный акселерометр | ≈0.005–0.01° по шуму, но заметнее уход нуля от температуры | если нужна тишина сигнала; модуль EVAL-ADXL355-PMDZ |
| MPU-6050 (GY-521) | I2C | дешёвый акселерометр+гироскоп | ≈0.05–0.1°, сильный дрейф | только проверить провода, сайт, сервы |
| ADXL345, LIS3DH, SG-датчики «на шарике» | — | — | грубо | не брать |

\* после калибровки разворотом и усреднения; реальные цифры зависят от модуля — сверяйте с даташитом.

Как выбирать модуль SCL3300: нужен переходник с выведенными VDD (3.3 В), GND, SCK, MISO, MOSI, CS
(оценочная плата Murata или сторонний breakout). Три одинаковых модуля на общей шине SPI, у каждого свой CS.
Готовые промышленные инклинометры с RS-485 (класс 0.01°) тоже подойдут для большой установки,
но им нужен преобразователь MAX3485 и отдельный драйвер — в прошивке их пока нет.

## Сервоприводы для самовыравнивания

| Серва | Как управляется | Шаг | Итог для платформы 200 мм |
|---|---|---|---|
| **Feetech STS3215** | шина UART 1 Мбит/с, своя обратная связь | 0.088° (энкодер 4096/об) | **рекомендую**: с рычагом 15 мм ≈0.023 мм на шаг → горизонт ≈0.01° |
| DS3218 (металлический редуктор) | ШИМ 50 Гц | мёртвая зона ~0.3° | грубее: ≈0.02–0.04°, может подрагивать |
| MG996R | ШИМ | ~0.5°, люфт | только для опытов |
| SG90 и пластиковые | ШИМ | люфт | не брать |

Нагрузка тут маленькая (плита ~0.7 кг — меньше 1 кг·см на серву), поэтому выбираем по точности, а не по силе.
Точность = длина рычага × шаг сервы: **короче рычаг — точнее, но меньше ход**. Рычаг 15 мм даёт ход ±11.5 мм (≈±4°).

Что нужно для STS3215:
- 3 сервы STS3215 (версия 7.4 В или 12 В) и блок питания под них на 3+ А. **Общий GND с ESP32**, питание серв — не от ESP32.
- Адаптер шины Feetech (URT-1 или аналог от Waveshare) **или** провод TX ESP32 (GPIO 17) → линия данных шины
  (прошивка только пишет команды, ответы не читает).
- **ID серв 1, 2, 3**: с завода у всех ID 1 — поменяйте программой Feetech FD по одной серве.
- Центр: в `include/config.h` `STS_CENTER` — позиция, при которой рычаг горизонтален (по умолчанию 2048).

Механика: серва под каждой опорой A, B, C, рычаг 15 мм, вертикальная тяга с шаровыми наконечниками M3 до платформы.
Сервы держат положение **только под током**: при отключении питания платформа опустится (для стенда это не страшно).

Для обычных ШИМ-серв — окружение `scl3300-pwm`, сигналы на GPIO 32 / 14 / 13, центр и направление — `SERVO_CENTER_US`, `SERVO_DIR`.

## Раскладка на плите (вид сверху, Y — от вас)

```
        ┌──────────────────────┐  +Y (назад)
        │          C           │   опора C (0, 85)
        │         [3]          │   датчик 3 (0, 70)
        │                      │
        │                      │
        │  [1]            [2]  │   датчики 1 (−70,−70), 2 (70,−70)
        │ A                  B │   опоры A (−85,−85), B (85,−85)
        └──────────────────────┘  → +X (вправо)
```

Датчики ставьте одинаково ориентированными: оси X всех трёх — вправо, Y — от вас.
Если повернули — укажите `SENSOR_MOUNT` в `include/config.h`.
**Проверка:** приподнимите правый край — X на сайте должен расти; задний край — Y должен расти.

## Подключение

**SCL3300 или ADXL355 (SPI, питание 3.3 В — не 5 В!)**

| Датчик | ESP32 |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SCK / SCLK | GPIO 18 |
| MISO / SDO | GPIO 19 |
| MOSI / SDI | GPIO 23 |
| CS датчика 1 / 2 / 3 | GPIO 5 / 4 / 27 |

**MPU-6050 (I2C)**

| Датчик | SDA | SCL | AD0 |
|---|---|---|---|
| 1 | GPIO 21 | GPIO 22 | GND (адрес 0x68) |
| 2 | GPIO 21 | GPIO 22 | 3V3 (адрес 0x69) |
| 3 | GPIO 25 | GPIO 26 | GND (вторая шина) |

Провода к датчикам — до 20–30 см, иначе SPI начнёт сбоить (тогда снизьте частоту в `sensors.cpp`).

## Прошивка

1. Установите VS Code и расширение **PlatformIO**.
2. Откройте папку `firmware/esp32-leveler`.
3. Wi-Fi (по желанию): скопируйте `include/secrets.example.h` в `include/secrets.h` и впишите сеть.
   Без этого ESP32 поднимет свою точку доступа **Leveler** (пароль `leveler123`), адрес 192.168.4.1.
4. Выберите окружение под датчики и прошейте:

```bash
pio run -e scl3300 -t upload
```

Окружения: `scl3300`, `adxl355`, `mpu6050`, `sim` (без датчиков — проверить сайт).

```bash
pio device monitor
```

В мониторе (230400 бод) видно JSON-строки и сообщения вида «датчик 1 (SCL3300): найден».

## Сайт

Запустите сайт из корня проекта и откройте `live.html`:

```bash
python3 -m http.server 8765
```

- **USB** — Chrome или Edge, источник «USB (Web Serial)», выберите порт платы. При подключении ESP32 может перезагрузиться — это нормально.
- **Wi-Fi** — источник «Wi-Fi», адрес `ws://leveler.local:81` (или `ws://IP:81`; IP видно в журнале и в мониторе порта).
  В режиме своей точки доступа: подключитесь к сети Leveler, адрес `ws://192.168.4.1:81`.
- **Демо без железа** — всё то же самое на виртуальной платформе.

## Эксперимент

1. Положите платформу на стол, подключитесь. Все три датчика «в работе».
2. **Калибровка разворотом:** «1. Замер» → разверните платформу на 180° на том же месте → «2. Замер».
   Смещения датчиков запишутся в плату (сохраняются после выключения), заодно увидите наклон стола.
   Если есть заведомо ровная поверхность — достаточно «Обнулить здесь».
3. **Ручное выравнивание:** выберите шаг резьбы и опору, которую не трогаете. Подкручивайте по подсказке
   («поднять на 0.20 мм ≈ 0.2 оборота»), пока всё не станет зелёным.
4. **Запись:** «Начать запись» → поэкспериментируйте (постучите, положите груз, подогрейте феном один датчик,
   оставьте на ночь) → «Скачать CSV».
5. Смотрите график «Расхождение датчиков»: так видно, как каждый датчик шумит и плывёт и когда голосование 2 из 3
   исключает неисправный.

## Протокол

Плата → сайт, JSON по строке, 20 раз в секунду:

```json
{"t":12345,"type":"SCL3300","hz":100.0,"n":3,
 "s":[{"p":1,"ok":1,"h":1,"x":0.0123,"y":-0.0045,"ux":0.05,"uy":-0.01,"tc":24.6,"nz":0.003,"r":""}],
 "f":{"x":0.0121,"y":-0.0043,"v":1,"u":3}}
```

`s` — датчики (`x/y` с калибровкой, `ux/uy` без неё, `h` — участвует в голосовании, `r` — причина исключения),
`f` — общий наклон (`v` — достоверен, `u` — сколько датчиков использовано). Ещё бывают `{"info":…}`, `{"log":…}`, `{"ack":…}`, `{"err":…}`.

Сайт → плата, текстом по строке: `info`, `zero`, `clear`, `offsets x1 y1 x2 y2 x3 y3`, `tau 0.5`, `rate 20`, `reset`, `sim x y`,
и для серв: `auto 1` / `auto 0`, `home` (все в нейтраль), `height мм` (общий подъём), `servo i мм` (вручную, i = 0…2), `tol °`, `ki`.
В состоянии с сервами есть блок `"m":{"auto":1,"st":2,"h":0,"z":[…]}`: `st` 0 — ручной, 1 — выравнивание, 2 — ровно, 3 — не хватает хода, 4 — нет данных.

## Проверено

- `test/host/run.sh` — ядро (наклон, CRC SCL3300, голосование, отказы, команды, JSON) и замкнутый контур
  «стол → сервы с рычагом → датчики → выравнивание»: 43 проверки, собирается обычным `c++`.
- `test/host/check_syntax.sh` — синтаксис Arduino-части для всех сочетаний датчиков (4) и серв (нет/ШИМ/шина) на заглушках API.
- **Не проверено:** сборка настоящим тулчейном ESP32 и работа с реальными датчиками — первая прошивка покажет.
  Команды SCL3300 сверены по контрольным суммам; регистры ADXL355, MPU-6050 и протокол Feetech STS — по документации.

## Самовыравнивание

1. Откалибруйте датчики (выше), поставьте сервы в нейтраль — кнопка «Нейтраль».
2. «Включить авто»: плата сама двигает сервы, пока наклон не войдёт в допуск, дальше держит и не дёргается.
3. Ползунок «Общий подъём» поднимает всю платформу, не нарушая горизонт.
4. Наклоните стол или положите груз — платформа выровняется снова. «Не хватает хода» — подложите что-нибудь под низкую сторону.

Без железа то же самое можно проверить в демо на сайте или прошивкой `sim` прямо на плате.
